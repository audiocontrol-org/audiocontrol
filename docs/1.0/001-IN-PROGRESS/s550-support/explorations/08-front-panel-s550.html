S-550 — Control Surface

v1 built pretty chrome around a control surface. v2 IS the control surface. Stripped: LCD, numeric keypad, status-LED strip, rack ears, badges, screws. None of those are controls. The S-550 hardware photo proves the design language is a matte black chassis with chunky rubberized buttons — no decoration. The buttons ARE the design.

Controls match the existing S-330 VirtualFrontPanel component exactly: 4 navigation arrows, 2 value buttons, 5 function buttons. Visual aesthetic taken from the operator's reference photo: chunky black plastic, white silkscreen labels, red arrow glyphs. Press a button → it lands as useFrontPanel.pressButton(id) just like on the S-330.

Production mapping

Every <button data-fp="X"> in this mockup maps to a FrontPanelButton render in the existing React component. Click → useFrontPanel.pressButton(X). No new button identifiers, no new hook surface. The S-550 variant is a layout + styling change ONLY — same controls, same behavior, same SysEx out.

Aesthetic — taken from hardware

Matte black chassis. Chunky molded-plastic button surfaces with a faint top-edge highlight (front-lit on the real hardware) and a near-black bottom. Hairline bezel grooves between buttons. White silkscreen for function/value labels; red silkscreen for the four arrow glyphs — same color contrast the photo shows. No decorative chrome anywhere.

Pressed-state LED

A small red LED dot appears on the top-left of a button when it's actively pressed — homage to the PLAY LED on the real hardware, repurposed as keyboard-press feedback. The mouse :active alone isn't visible during keyboard-driven presses; the LED makes the input land. Functional, not decorative.

Keyboard shortcuts

Same as the S-330 component: ↑ ↓ ← → for navigation, + − for value, F1 F2 F3 F4 F5 for MODE / MENU / SUB / COM / EXEC. Bindings live in useFrontPanel.ts; the S-550 layout inherits them unchanged.

Layout — mirrors the hardware photo

7-column × 2-row grid, three cells blank to preserve the cross arrow cluster's visual identity. Row 1: function group left (MODE/MENU/SUB), arrow UP centered, COM right. Row 2: value group left (DEC/INC), arrow LEFT/DOWN/RIGHT centered, EXEC right. Same physical rhythm a user trained on the hardware would expect.

What v2 deliberately does NOT have

No LCD, no numeric keypad, no status-LED strip, no rack ears, no badges, no screws. v1 had all of those — every one was invented decoration that drowned the actual interface. None of them are controls; the panel exists to fire controls; therefore none of them belong here.
