# Build Optimization — Product Requirements Document

**Created:** 2026-03-22
**Status:** Draft
**Owner:** Orion Letizi

## Problem Statement

The audiocontrol monorepo build (`make build`) rebuilds all 24 modules on every invocation, even when only one file has changed. A full build takes significant time because:

1. **Makefile stamp files don't track source changes.** Each module's `.build-stamp` depends only on other stamps and `$(INSTALL_STAMP)`, never on actual source files. Make cannot detect when `.ts` files change, so it either rebuilds everything (after a clean) or rebuilds nothing (if stamps exist), with no middle ground.

2. **TypeScript incremental compilation is disabled in most modules.** `tsconfig.base.json` sets `incremental: true` and `composite: true`, but 10 modules override with `incremental: false` in their own tsconfig. The `.tsbuildinfo` files that enable incremental builds are gitignored and not generated by these modules.

3. **Tests are coupled to build scripts.** Four modules (`sampler-lib`, `sampler-devices`, `sampler-library`, `loop-editor`, `sample-chopper`) run their full test suite as part of `pnpm build`. This means every build — even when nothing changed — runs tests that should only run on `pnpm test`.

4. **Mixed build tooling with no shared incremental story.** The repo uses tsc (8 modules), tsup (8 modules), vite (5 modules), and rollup (1 module). Each tool has different caching behavior, and none are wired into Make's dependency graph.

### Impact

- Slow iteration loop: changing one file in one module triggers a full rebuild
- CI builds are slower than necessary
- Developers avoid running `make` and use ad-hoc per-module builds, losing dependency ordering guarantees

## User Stories

- As a developer, I want `make build` to only rebuild modules whose source files have actually changed, so that incremental builds complete in seconds rather than minutes.
- As a developer, I want tests separated from builds so that `make build` is fast and `pnpm test` is the explicit test path.
- As a developer, I want consistent build tooling configuration across modules so that incremental build behavior is predictable.

## Success Criteria

- [ ] `make build` with no source changes completes in under 5 seconds (stamp check only)
- [ ] Changing one `.ts` file in a leaf module triggers a rebuild of only that module and its dependents
- [ ] No module runs tests as part of its `build` script
- [ ] TypeScript incremental compilation is enabled across all tsc-based modules
- [ ] Full clean build (`make clean && make`) still produces correct output for all modules

## Scope

### In Scope

- Makefile: add source file dependencies to stamp file rules
- Module tsconfig.json: enable incremental compilation consistently
- Module package.json: separate test from build in build scripts
- Verify tsup/vite caching behavior and document

### Out of Scope

- Migrating modules between build tools (e.g., tsup to vite or vice versa)
- Adding TypeScript project references (`tsc -b` across the entire repo)
- CI pipeline changes (separate task once local builds are fast)
- Parallel make (`make -j`) — can be a follow-up once dependencies are correct
- Changing the module dependency graph itself

## Dependencies

- GNU Make (already in use)
- pnpm workspaces (already in use)
- Existing build tools per module (tsc, tsup, vite, rollup)

## Open Questions

- [ ] Should tsup/vite modules also use Make source dependencies, or rely on their own caching?
- [ ] Is `$(shell find ...)` performant enough for 24 modules, or should we use a file-list cache?
- [ ] Should `.tsbuildinfo` files be committed or remain gitignored?
